# Syndicate NPP Monitor — публичный сайт АЭС

**Готовый Node.js-проект без npm-зависимостей**. Показывает показания игрового реактора ИР-60, турбины К-2,5-35 и энергосистемы города. Посетители видят показатели в браузере, но не могут отправлять телеметрию без секретного ключа и не управляют станцией.

## Что сделано

- Публичный сайт `/` — график мощности, генерация / нагрузка / резерв, реактор, ТВЭЛ, износ, турбина, насосы, отходы, неисправности, события.
- HTTP API: `POST /api/ingest` с ключом `Authorization: Bearer <INGEST_TOKEN>`.
- `GET /api/state` и `GET /api/events` (Server-Sent Events) для просмотра в реальном времени, `GET /health` для платформы хостинга.
- Обновления в браузере сразу после получения данных; потеря связи отмечается через 12 секунд (регулируется).
- Пропуск неизвестных полей — включая SteamID, имена игроков, адреса сервера, банковские данные. Это **публичный** сайт.
- Последний час графика хранится **в памяти процесса**. Если сервер сайта перезапустится, история исчезнет; для постоянного архива в будущем нужна база данных.
- Есть отдельный явно маркированный деморежим, по умолчанию **нет ложных данных**.
- Никаких функций включения, выключения или управления АЭС через сайт.

## Запуск на своём ПК

1. Установить Node.js 20+.
2. Открыть терминал в папке проекта.
3. Сгенерировать длинный секрет (например, в PowerShell: `[Convert]::ToHexString((1..32 | ForEach-Object {Get-Random -Minimum 0 -Maximum 256}))`; либо используйте менеджер паролей).
4. Задать ключ и запустить:

   **Windows PowerShell:**

   ```powershell
   $env:INGEST_TOKEN = "ВСТАВЬ_СВОЙ_ДЛИННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ"
   npm start
   ```

   **macOS/Linux:**

   ```bash
   export INGEST_TOKEN='YOUR_LONG_RANDOM_SECRET'
   npm start
   ```

5. Открыть `http://localhost:3000`.
6. Проверить на демоданных: в **другом** терминале установить те же `INGEST_TOKEN` и `NPP_SITE_URL=http://localhost:3000`, запустить `python bridge/demo_sender.py`. На сайте появится **ДЕМО**. Остановить `Ctrl+C` и убедиться, что спустя 12 секунд появится **Нет связи**.

## Сделать сайт общедоступным по ссылке

Один простой вариант — хостинг **Render** (https://render.com/docs/web-services):

1. Создать свой репозиторий GitHub, загрузить **содержимое этой папки** (не выкладывать `.env` и реальные секреты).
2. Render → **New → Web Service** → привязать репозиторий.
3. Runtime: **Node**, Build command: `npm install`, Start command: `npm start`.
4. Environment variables: `INGEST_TOKEN` = ваш длинный случайный ключ; при желании `STALE_SECONDS=12`.
5. После деплоя Render выдаст публичный HTTPS-адрес вида `https://ваш-сайт.onrender.com`. **Это пример формата, не уже созданный адрес**.
6. Любой человек сможет открыть URL и смотреть показатели; опубликование сайта само по себе **не соединит его с Garry's Mod**.

Важно: бесплатные сервисы могут «засыпать», а история в памяти будет теряться при перезапусках. Для устойчивого 24/7 нужна подходящая платная конфигурация либо другая постоянная среда. Убедитесь, что политика сервера разрешает публичную трансляцию игровых показателей.

## Как отправить данные на сайт

Нужны JSON-данные из **уже разрешённого** источника:

```json
{
  "source": "live",
  "s": {"run": true, "fuelSec": 900,
        "city": {"station": 1750, "load": 2000, "reserve": 250},
        "rx": {"chans": 60, "fresh": 50, "spent": 10, "wear": 0.75},
        "tb": {"rpm": 3000, "load": 1.75}}
}
```

В `examples/realistic_shape.json` — расширенный пример **синтетических** значений. Команда однократной отправки:

```bash
# Указать NPP_SITE_URL (HTTPS-URL вашего опубликованного сайта)
# и INGEST_TOKEN (тот же секрет, который задан на сайте), затем:
python bridge/send_json.py examples/realistic_shape.json
```

Для регулярной передачи JSON-файла существует `bridge/watch_file.py`:

- `NPP_JSON_PATH` — путь к файлу `garrysmod/data/syndicate_npp_monitor.json`;
- `NPP_SITE_URL` — публичный HTTPS-адрес;
- `INGEST_TOKEN` — секрет, не в браузере и не в репозитории;
- запустить `python bridge/watch_file.py`.

**Пока файл в игре не появляется, реального мониторинга нет**. Скрипт не подделывает данные и не обновляет устаревший файл повторно.

## Можно ли достать эти данные без изменения сервера Garry's Mod?

В архиве Lua-скриптов есть приложение телефона `SPHONE.NPP`, которое получает существующее сетевое сообщение `synd_phone_npp_state`, распаковывает JSON и сохраняет его в `SPHONE.NPP.S.st`. При открытии приложения клиент отправляет сообщение `synd_phone_npp_open`; сервер проверяет подписку и роль. `SPHONE.NPP.CFG.TICK=2`, `KEEP=25`, `PING=8`, `TIMEOUT=10` указаны в `npp_shared.lua`.

В `bridge/optional_client_export.lua` есть **пример для разрешённой клиентской Lua-среды**. Он записывает уже полученную сводку (без банковских данных/информации о смене) в `garrysmod/data/syndicate_npp_monitor.json`, после чего отдельная программа Python пересылает её на публичный сайт. Скрипт **не подключится сам** на сервере с `sv_allowcslua 0`, если пользователь не имеет разрешённого способа загрузки клиентского Lua; не используйте инъекции и обход ограничений. При закрытом телефонном приложении подписка прекращается и сайт должен показать потерю связи.

**Без разрешённого клиентского источника** возможен только внешний сборщик по видимым данным экрана (например, захват игры и распознавание чисел); точность ограничена тем, что видно в интерфейсе. Другой вариант — договориться с администрацией о предоставлении легального источника данных. Оба пути не требуют менять внутреннюю симуляцию АЭС.

## Безопасность и ограничения

- Публичен просмотр; запись защищена `INGEST_TOKEN` и рассчитана только на **HTTPS** при публичном размещении.
- Не передавайте секрет посторонним; не вставляйте его в публичный JavaScript, URL или общедоступные чаты.
- Секрет лучше хранить в переменной окружения Windows на компьютере-отправителе и в настройках хостинга.
- Поступающие данные проверяются по формату и пропускаются через whitelist публичных полей; текст выводится безопасно.
- Сайт не проверяет независимым способом, «правдивы» ли данные от источника, который владеет токеном. Поэтому храните токен в тайне.
- История пропадает при перезапуске, так как хранения в базе нет. Обслуживание нескольких экземпляров потребует общей БД/шины событий.
- Если сервер не прислал показатель, показывается «—», а не выдуманный ноль.
- Пример экспортера работает только тогда, когда код действительно загружен клиентом и телефон уже получает состояние.

## Файлы проекта

- `server.js` — сайт, HTTP API, события, отключение по тайм-ауту.
- `telemetry.js` — фильтрация данных до публичного набора.
- `public/index.html`, `public/styles.css`, `public/app.js` — интерфейс.
- `bridge/watch_file.py` — безопасный пересыльщик локального JSON-файла.
- `bridge/optional_client_export.lua` — **необязательный** клиентский экспорт в файл, только при разрешённом выполнении Lua.
- `bridge/demo_sender.py` — синтетические данные (помечены ДЕМО).
- `bridge/send_json.py` — разовая отправка JSON.
- `render.yaml` — пример конфигурации хостинга.

**Источник названий и полей:** предоставленный `all_lua.zip`, файлы, распакованные при анализе в `npp_analysis/npp_phone.lua` и `npp_analysis/npp_shared.lua`. Серверных исходников подписки может не быть в клиентском кэше, и их алгоритмы не заявлены как проверенные.
